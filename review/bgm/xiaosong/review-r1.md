## 第 3 項：循環接點

**這一版的做法變了。** 每個檔案前後各多放 192 毫秒的「同一圈的延續」（不是靜音），播放器解碼後從中間切出完整一圈，放進獨立的 buffer 循環。好處是 mp3 和 ogg 在檔頭檔尾多出來或少掉的樣本，都落在緩衝區裡，不會進到循環。

我量到的：

- **緩衝區是真的同一圈**：檔頭、檔尾沒有任何數位靜音，緩衝區音量 −15～−23 dBFS。
- **接點**：28 檔的喀聲指標全部低於曲內小節線最大值；尾端連續近靜音全部 0 ms；接點前 150 毫秒內最安靜的 10 毫秒是 −32 dBFS（lamplight），沒有洞。
- **B 的 6 毫秒縫**：journey 接點凹洞 1.9／0.0 dB（曲內最大 8.6），沒有復發。
- **C 的 122 毫秒尾巴**：candy 尾端靜音 0 ms，接點前最安靜的 10 毫秒是 −20 dBFS，沒有復發。
- **唯一貼線的**：theater 的 mp3 接點凹洞 10.3 dB，和曲內最深的那條小節線一樣深（Chromium 裡是 10.43 對 10.28，深 0.15 dB）。這首低音多，2 毫秒的窗本來就會隨波形起伏；它過了小夏自訂的「不超過曲內最大 +1 dB」，我判斷聽不出來，但它是 28 檔裡最接近門檻的。

**瀏覽器實測**（Chromium，14 首 × mp3／ogg × 48k／44.1k 共 56 組）：

- 用遊戲自己的 `prepareLoopBuffer` 切出一圈，交給 AudioBufferSourceNode 以 `loop=true`、`loopStart=0`、`loopEnd=一圈長度` 渲染 2.25 圈，和「一圈頭尾直接相接」比，最大差 0.0000000001。也就是引擎循環沒有多塞或少掉任何樣本。
- 56 組的接點喀聲都不高於曲內小節線最大值。上一輪「C 的 mp3 在 44.1k 偏尖」的問題這版沒有了。
- mp3 補零：Chromium 有照檔頭的無縫標記裁掉，48k 解碼長度 14 首都剛好。
- ogg 尾塊：見上表，多出來的那段有聲音（峰值到 0.22），但落在緩衝區之後，不會進循環。

**如果瀏覽器不理 mp3 的無縫標記會怎樣**：我在遊戲頁面裡攔截解碼結果，在前面硬塞 1105 和 2257 個零樣本（模擬不裁補零的解碼器），再讓遊戲照常播放。4 首都還是走 Web Audio，拿去播的那一圈裡沒有混進補零，接點喀聲和沒塞的時候差不多。所以這個設計對補零是有容忍度的。這是模擬，不是 Safari 實測。

**macOS 的參考數字**：用系統的 `afinfo` 看，CoreAudio 認得這些 mp3 的無縫標記，有效長度 14 首都剛好；它也讀得了這些 ogg。Safari 用的是同一套解碼，這是好兆頭，但不等於 Safari 測過。

## 問題

擋這一輪的：

- **A. 沒有公開測試網址和測試步驟**（第 11 項）。
- **B. README 的 ogg 尾端數字沒改**（第 10 項）。

不擋這一輪，但實機測試前建議處理：

1. **iPhone 可能不會自己出聲。** 解鎖只掛在「手指按下」（pointerdown）和鍵盤。依網頁標準，觸控的「按下」不算使用者啟動，「放開」才算；iPhone Safari 一向也是這樣。舊版遊戲有同樣寫法還能出聲，我推測是因為按鈕音效在「點擊」時啟動了音訊。如果是這樣，玩家把音效關掉時，iPhone 上背景音樂可能永遠不會開始。這是我讀程式的推論，沒有實機可以驗。
2. **三首在手機喇叭上會明顯小聲。** hate 有 97% 的能量在 500 Hz 以下、bagvalley 89%、theater 78%，1 kHz 以上幾乎是空的。手機小喇叭播不太出 400 Hz 以下，濾掉後估計 hate 是 −24.9、bagvalley −22.6、theater −22.0 LUFS，其他首大多在 −17 上下，差了 5～8 dB。用耳機聽不會有這個問題。
3. **`<audio>` 退路在 iPhone 上關不掉音樂。** 退路的靜音是把音量設成 0，但 iPhone 不允許網頁改 `<audio>` 的音量。舊版是直接停播所以沒這個問題。只有走到退路才會發生。
4. **試聽頁和遊戲的行為不一致。** 試聽頁預設 OGG，遊戲優先用 MP3；試聽頁對 mp3 多出的樣本只容許 2 個，遊戲容許到 4096 個。在 iPhone 上可能出現試聽頁報錯、遊戲卻能播的情況，會讓實機測試的結論混淆。
5. **關掉音樂後進新地區還是會下載和解碼。** 增益是 0 但照樣抓 600～800 KB、解成 13～19 MB。對用行動網路的人是浪費。
6. **換區時新曲沒抓完之前，舊曲會繼續播。** 這是設計（避免中間沒聲音），網路慢時畫面已經換區、音樂晚一兩秒才換。請我的王實機時留意能不能接受。
7. **每次進場景都從檔案開頭播**，而檔案開頭最多在第一拍之前 350 毫秒，所以進場會先聽到一小段上一小節的尾巴。README 有寫。
8. **PR 說明和 README 關於我的那句要更新。** 現在寫「小頌只讀交叉檢查……沒有獨立重跑測試」，這次我是親自跑的，請改成引用這份報告。
