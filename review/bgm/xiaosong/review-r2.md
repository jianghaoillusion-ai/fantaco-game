## 接點（第 3 項）

做法和上一輪相同：每個檔案前後各多放 192 毫秒「同一圈的延續」（不是靜音），播放器解碼後從中間切出完整一圈，放進獨立的 buffer，用 `loop=true`、`loopStart=0`、`loopEnd=一圈長度` 循環。mp3 和 ogg 在檔頭檔尾多出來或少掉的樣本都落在緩衝區，不會進到循環。

- **音檔直接量**：28 檔頭尾沒有數位靜音；接點喀聲全部低於曲內小節線最大值；尾端連續近靜音全部 0 毫秒；接點前 150 毫秒內最安靜的 10 毫秒是 −32 dBFS（lamplight），沒有洞。
- **B 的 6 毫秒縫**：journey 接點凹洞 1.9／0.0 dB（曲內最大 8.6），沒有復發。
- **C 的 122 毫秒尾巴**：candy 尾端靜音 0 毫秒，沒有復發。
- **上一輪唯一貼線的 theater**：改高八度後接點凹洞從 10.3 dB 降到 0，不再貼線。
- **瀏覽器實測**（14 首 × mp3／ogg × 48k／44.1k 共 56 組，本機和公開網址各跑一次）：用遊戲自己的函式切出一圈，交給 AudioBufferSourceNode 渲染 2.25 圈，和「一圈頭尾直接相接」比，最大差 0.0000000001。引擎循環沒有多塞或少掉任何樣本。56 組的喀聲和凹洞都不比曲內小節線差。
- **mp3 補零**：Chromium 有照檔頭的無縫標記裁掉，48k 解碼長度 14 首都剛好。我另外在遊戲頁面裡硬塞 1105、2257 個零樣本模擬不裁補零的解碼器，4 首都還是走 Web Audio，接點喀聲和沒塞時差不多。這是模擬，不是 Safari 實測。

- **curl**：兩個頁面和 js、json 都是 200，內容和 repo 逐位元組相同。32 個音檔 githack 會先回 301 轉到 GitHub 的原始檔主機，跟著轉過去是 200，MIME 正確（audio/mpeg、audio/ogg、audio/mp4），內容和 repo 逐位元組相同，也允許跨來源讀取。
- **無頭瀏覽器**：先出現英文中繼頁，按「Open the page」後進得去。上面整套檢查在這個網址重跑一次，結果和本機相同：28 檔 56 組解碼與循環都過、進地區各播 1 次、不重疊、快取最多 3 首、試聽頁 28 次都能播、`<audio>` 退路能播、0 個 JS 錯誤。

## 問題（都不擋這輪）

1. **PR 說明和 README 關於我的那句要更新。** 現在寫「小頌第 2 輪是靜態程式碼審查、沒有獨立重跑」。那是 15:20 協作橋的意見；這份是實跑的，請改成引用這份報告。
2. **公開網址是別人的免費服務。** 有中繼頁、有廣告；音檔和圖片是轉址到 GitHub 讀的。我在公開網址跑的時候，有兩張角色頭像（jiejie-happy）載入失敗，但檔案確實存在、單獨抓得到，本機也沒這個問題。所以我的王在測試網址上如果看到頭像破圖，是這個服務的問題，不是遊戲壞掉。音檔沒有任何一次失敗。
3. **hate 還是偏悶。** 提高八度後小喇叭估計音量夠了，但 1 kHz 以上的能量只有 1%，頻譜重心 574 Hz。音量不是問題，音色亮不亮要用耳朵聽。
4. **試聽頁 10 毫秒連點**時，中間有一首被短暫起了一下又停掉才換到最後那首。前後接續、沒有疊音，人手也點不到這麼快。只是試聽頁，遊戲本體沒有這個情況。
5. **靜音時音源還在跑**（增益 0）。小夏有寫是取捨，會多耗一點電。
6. **換區時新曲沒抓完之前舊曲會繼續播**；**進場可能先聽到最多 350 毫秒的上一小節尾巴**。兩個都是設計，小夏有寫，測試步驟也提醒了。公開網址上我量到按下到換曲是 0.35～1.2 秒。
