# 地圖主循環實作計畫

目標：依 brief-v2 與 brief-v3-map，交單取得遊戲資源，逐步修復微笑村／城堡並解鎖後續區域；所有狀態可重讀。
架構：沿用靜態 ES modules；map-loop.js 管理交易與修復，shop-logic.js 管理免費遊戲貨幣購買，map-adapter.js 隔離暫定資料格式。app.js 只接狀態、操作與事件；不改故事對白、自適應格數演算法及官方素材。

1. 先新增修復、扣款原子性、商店、schema 遷移測試並觀察失敗；實作純邏輯與資料；測試通過後提交。
2. 新增迷霧小島、附近生成冷卻、旋轉保物、每日挑戰測試並觀察失敗；接存檔與 app UI 掛勾；跑所有測試後提交。
3. 驗證實際訂單→修復→新區域→商店→重讀流程，更新數值與事件文件；fetch/merge main 後再測試，提交／push 分支／開 PR／交叉審查。

驗收重點：資源不足零扣款、重複修復不領重複獎、背包滿不吞物、午夜台北重置、舊存檔與未來 schema 不覆寫、不同尺寸不丟失物品與迷霧進度。main 尚未有 map.json；開 PR 前再對齊。
